# microtun-cli

A clap-like `no_std` async Telnet CLI library for embedded Rust.

`microtun-cli` is a `no_std`, async Telnet CLI framework for embedded Rust. Define commands
with familiar clap-style derives and attributes, then run them through an interactive `Session` with
static dispatch, bounded memory, zero-copy argument parsing, command history, completion, and real
Telnet protocol handling—all without requiring a heap.

```rust
#![no_std]

use core::net::Ipv4Addr;
use embedded_io_async::Write;
use microtun_cli::{
    write_fmt, Dispatch, Error, ErrorKind, Parser, Subcommand, ValueEnum,
};

struct Device;

#[derive(Clone, Copy, Debug, ValueEnum)]
enum LogLevel {
    Error,
    Warn,
    Info,
    Debug,
    Trace,
}

impl Device {
    async fn status<W: Write<Error = ErrorKind> + ?Sized>(
        _this: &mut Self,
        out: &mut W,
        verbose: bool,
    ) -> Result<(), Error> {
        out.write_all(b"status: ok\r\n").await?;
        if verbose {
            out.write_all(b"network: up\r\n").await?;
        }
        Ok(())
    }

    async fn static_ip<W: Write<Error = ErrorKind> + ?Sized>(
        _this: &mut Self,
        out: &mut W,
        address: Ipv4Addr,
        prefix: u8,
    ) -> Result<(), Error> {
        write_fmt::<64, _>(out, format_args!("address: {address}/{prefix}\r\n")).await
    }

    async fn dhcp<W: Write<Error = ErrorKind> + ?Sized>(
        _this: &mut Self,
        out: &mut W,
    ) -> Result<(), Error> {
        out.write_all(b"dhcp: enabled\r\n").await?;
        Ok(())
    }

    async fn set_log<W: Write<Error = ErrorKind> + ?Sized>(
        _this: &mut Self,
        out: &mut W,
        level: LogLevel,
    ) -> Result<(), Error> {
        write_fmt::<64, _>(out, format_args!("log level: {level:?}\r\n")).await
    }
}

#[derive(Subcommand, Dispatch)]
#[dispatch(context = Device)]
enum NetCommand {
    /// Configure a static IPv4 address.
    #[command(handler = Device::static_ip)]
    Static {
        address: Ipv4Addr,

        #[arg(short, long, default_value_t = 24)]
        prefix: u8,
    },

    /// Enable DHCP.
    #[command(handler = Device::dhcp)]
    Dhcp,
}

#[derive(Parser, Dispatch)]
#[command(
    name = "device",
    version = "0.1.0",
    about = "Embedded device management console"
)]
#[dispatch(context = Device)]
enum Command {
    /// Show device status.
    #[command(handler = Device::status)]
    Status {
        #[arg(short, long)]
        verbose: bool,
    },

    /// Network configuration.
    Net {
        #[command(subcommand)]
        command: NetCommand,
    },

    /// Configure logging.
    #[command(handler = Device::set_log)]
    Log {
        #[arg(value_enum)]
        level: LogLevel,
    },
}
```

After accepting a TCP socket:

```rust,ignore
use microtun_cli::{Config, Session};

Session::<_, 256, 8, 256>::new(
    socket,
    Config::new("device> ").banner("ACME controller"),
)
.serve::<CommandParser, _>(&mut device)
.await?;
```

`CommandParser` is generated by `#[derive(Parser)]`. Its GAT-based parser family lets every command
invocation borrow the session's fixed input buffer, so fields like `&str` are zero-copy without
making the session itself permanently borrowed.

Command handlers use the standard `embedded_io_async::Write` trait directly. `Session` passes a
Telnet-aware `Console` writer whose error type is `ErrorKind`; use `Write::write_all` for normal output.
For bounded formatted output, `write_fmt::<N, _>` is a free helper with an explicit stack scratch
capacity rather than a custom writer trait.

## Design goals

- `#![no_std]` runtime crate.
- No `alloc` by default, no `Box`, no dynamic command registry. An opt-in `alloc` feature adds
  owned `String` and `Vec<T>` argument support.
- Async I/O using `embedded-io-async` 0.7.
- Directly usable with `embassy-net` 0.9 TCP sockets.
- `heapless` for fixed-capacity collections (`Vec`, `String`, `Deque`).
- Zero-copy borrowed command arguments when a field is `&str`.
- Generated static command/help/completion metadata in flash.
- No boxed futures; generated dispatch is static.
- Real Telnet framing and option negotiation rather than treating Telnet as plain TCP.
- A clap-shaped API so existing clap knowledge transfers.

The proc-macro crate uses `std`, `syn`, and `quote` on the host. That has no impact on the embedded
runtime's allocation requirements.

## Clap-like derives

The derive vocabulary intentionally mirrors clap:

```rust
use microtun_cli::{Args, Parser, Subcommand, ValueEnum};
```

In v0.1, derive inputs may have at most one lifetime parameter; type and const generics are not
supported by the proc macros.

### `Parser`

A root command can be an enum:

```rust
#[derive(Parser)]
#[command(name = "device", about = "Device console", version = "1.0.0")]
enum Command {
    Info,
    Reboot {
        #[arg(long, default_value_t = 0)]
        delay_ms: u32,
    },
}
```

or a clap-style root struct containing a subcommand:

```rust
#[derive(Parser)]
#[command(name = "router")]
struct Cli<'a> {
    #[arg(short, long, global = true)]
    verbose: bool,

    #[command(subcommand)]
    command: Command<'a>,
}
```

`#[derive(Dispatch)]` also works on this struct shape and forwards to the
`#[command(subcommand)]` field.

### `Subcommand`

Nested subcommand trees are first-class:

```rust
#[derive(Subcommand)]
enum Command<'a> {
    Net {
        #[command(subcommand)]
        command: NetCommand<'a>,
    },
}

#[derive(Subcommand)]
enum NetCommand<'a> {
    Show,
    Static {
        address: core::net::Ipv4Addr,

        #[arg(long)]
        label: Option<&'a str>,
    },
    Dhcp,
}
```

This yields the expected grammar:

```text
device> net show
device> net static 192.168.1.20 --label office
device> net dhcp
```

Tuple variants containing one `Args` type are also supported:

```rust
#[derive(Args)]
struct PingArgs {
    host: core::net::IpAddr,

    #[arg(short = 'c', long, default_value_t = 4)]
    count: u8,
}

#[derive(Subcommand)]
enum Command {
    Ping(PingArgs),
}
```

### `Args` and `flatten`

Reusable groups use the normal clap pattern:

```rust
#[derive(Args)]
struct NetworkOptions {
    #[arg(long)]
    timeout_ms: Option<u32>,

    #[arg(long)]
    retries: Option<u8>,
}

#[derive(Args)]
struct PingArgs {
    target: core::net::IpAddr,

    #[command(flatten)]
    network: NetworkOptions,
}
```

The flattened schema is recursively visible to parsing and completion without constructing a
runtime registry. Help also flattens nested groups using an eight-entry fixed-capacity traversal
stack; groups deeper than that capacity are skipped.

### `ValueEnum`

```rust
#[derive(ValueEnum)]
enum Mode {
    AccessPoint,

    #[value(name = "sta", alias = "station", visible_alias = "station-mode")]
    Station,
}
```

With:

```rust,ignore
#[arg(value_enum)]
mode: Mode,
```

parsing, help, and tab completion use the generated static value table. `alias` values are
parse-only; use `visible_alias` when an alias should also appear in help and completion.

### Zero-copy strings

```rust
#[derive(Parser)]
enum Command<'a> {
    Connect {
        ssid: &'a str,

        #[arg(short, long)]
        password: Option<&'a str>,
    },
}
```

The lexer compacts quotes and escapes **in place** in the line buffer. The resulting `&str` points
directly into that buffer.

```text
device> connect "Lab WiFi" --password "hello world"
```

No owned `String` or separate string copy is required for either argument; the lexer only compacts
bytes within the existing line buffer.

## Argument forms

The derive parser currently implements the following clap-like forms:

```rust
#[arg(short)]
#[arg(short = 'p')]
#[arg(long)]
#[arg(long = "port")]
#[arg(short, long)]
#[arg(default_value_t = 23)]
#[arg(default_value_t)]
#[arg(value_enum)]
#[arg(value_name = "ADDRESS")]
#[arg(help = "Override the generated doc-comment help")]
#[arg(alias = "addr")]          // accepted by parsing, hidden from help/completion
#[arg(visible_alias = "address")]
#[arg(required = true)]
#[arg(global = true)]
#[arg(allow_hyphen_values)]
#[arg(action = ArgAction::Set)]
#[arg(action = ArgAction::SetTrue)]
#[arg(action = ArgAction::SetFalse)]
#[arg(action = ArgAction::Count)]
#[arg(action = ArgAction::Append)]
```

The normal type conveys additional semantics:

- `bool` + `short`/`long` -> `SetTrue` flag.
- `Option<T>` -> optional value.
- `heapless::Vec<T, N>` -> bounded repeated values (`Append`).
- `alloc::vec::Vec<T>` -> unbounded repeated values with the `alloc` feature.
- plain `T` without `short`/`long` -> positional.
- `&str` -> zero-copy positional/option value.
- `heapless::String<N>` -> explicitly copied bounded string.
- `alloc::string::String` -> owned string with the `alloc` feature.

`ArgAction::Set`, `SetTrue`, and `Append` are accepted when they match the behavior already implied
by the field type. The two explicit behavior overrides are `ArgAction::Count` (currently a `u8`
field) and `ArgAction::SetFalse` (a `bool` flag). `default_value_t` is only honored on plain,
non-flag, non-`Option`, non-repeated fields; literal defaults are included in static help metadata,
while computed expressions and bare `default_value_t` are applied at parse time but omitted from
help because there is no truthful static string to display.

### Short-option clustering and attached values

Boolean short flags can be clustered:

```text
device> command -vqf
```

`ArgAction::Count` supports repeated clustered flags:

```rust
#[arg(short, long, action = ArgAction::Count)]
verbose: u8,
```

```text
device> command -vvv
```

produces `verbose == 3`.

Option values accept:

```text
-p 23
-p23
-p=23
--port 23
--port=23
```

### Repeated values

The default remains allocation-free. Capacity is part of the type when using `heapless::Vec<T, N>`:

```rust
use heapless::Vec;

#[derive(Args)]
struct DnsArgs {
    #[arg(long)]
    server: Vec<core::net::Ipv4Addr, 4>,
}
```

```text
dns --server 1.1.1.1 --server 8.8.8.8
```

Repeated values use `heapless::Vec<T, N>` directly; the CLI crate does not wrap or alias it.

If a target has a global allocator, enable the optional `alloc` feature to use owned strings and
unbounded repeated values:

```toml
microtun-cli = { version = "0.4", features = ["alloc"] }
```

```rust,ignore
extern crate alloc;

use alloc::{string::String, vec::Vec};

#[derive(Args)]
struct Labels {
    name: String,

    #[arg(long)]
    tag: Vec<String>,
}
```

The runtime is still `#![no_std]`; enabling `alloc` only adds implementations backed by the
`alloc` crate. Fixed-capacity `heapless` types continue to work unchanged.

## Option and value syntax

Options accept both detached and attached values, and short options cluster:

```text
set --name device01
set --name=device01
set -n device01
set -nd
set -n=device01
set -vaf            # three short flags in one token
set -vafn device01  # flags followed by a value-taking short
```

Clustering is resolved against the schema: the first letter in a cluster that belongs to a
value-taking option consumes the rest of the token, so `-nfoo` is `--name foo` and never a
cluster that happens to contain an `f` flag.

A value that begins with `-` is rejected by default, because `--name --verbose` is nearly always
a forgotten value rather than a literal one:

```text
> set --name --verbose
error: option requires a value: name
```

Opt back in per argument with `#[arg(allow_hyphen_values)]`.

Two forms are always treated as values rather than options: a bare `-`, and negative numbers, so
a signed positional parses as written:

```text
set-offset -5
```

Everything after a `--` marker is a positional value, whatever it looks like:

```text
run -- --not-an-option -x
```

## Custom value parsing

Implement `FromArg`:

```rust
use microtun_cli::{FromArg, ValueError};

struct MacAddress([u8; 6]);

impl<'a> FromArg<'a> for MacAddress {
    fn from_arg(value: &'a str) -> Result<Self, ValueError> {
        // parse value without allocation...
        todo!()
    }
}
```

Built-in implementations are supplied for integer and floating-point types, booleans, chars,
`&str`, `heapless::String<N>`, and the `core::net` IP address types. With the `alloc` feature,
`alloc::string::String` is supported as well.

## Static async dispatch

Add a handler to a command:

```rust
#[derive(Parser, Dispatch)]
#[dispatch(context = Device)]
enum Command<'a> {
    #[command(handler = Device::echo)]
    Echo {
        text: &'a str,
    },
}
```

Handler shape:

```rust
impl Device {
    async fn echo<W: Write<Error = ErrorKind> + ?Sized>(
        _this: &mut Self,
        out: &mut W,
        text: &str,
    ) -> Result<(), Error> {
        out.write_all(text.as_bytes()).await?;
        out.write_all(b"\r\n").await?;
        Ok(())
    }
}
```

The macro generates a direct `match` and direct async calls. There is no `dyn Command`, `BoxFuture`,
or allocation. A variant with a `#[command(subcommand)]` field and no handler automatically forwards
dispatch to the nested enum. A leaf variant with no handler instead returns `Error::NoHandler`, which
`Session` reports as `error: command has no handler` without dropping the session.

## Help and completion

Static `CommandSpec`, `ArgSpec`, and `ValueSpec` data generated by the derives drives:

```text
device> help
device> help net
device> net --help
device> net static --help
device> --version
```

The `help` forms require the default `help` feature. `--version` / `-V` is handled independently of
that feature whenever the root schema has a version. Tab completion requires the default
`completion` feature and is schema-driven for subcommands, long options, and `ValueEnum` values.
Unknown or dynamic values never require a heap allocation.

When ambiguous candidates use the same replacement range and prefix and do not require quoting, Tab
inserts their longest shared prefix before listing them, so repeated presses can make progress.
Completion is quoting-aware: a partially quoted token such as `"my fi` is matched against its
logical text, and a candidate that would not survive re-lexing is re-quoted on insertion. Candidates
carry the absolute offset at which replacement begins, because the start of a quoted token cannot be
recovered by scanning back over whitespace.

## Terminal editor

The built-in editor supports:

- insertion/deletion in the middle of a line;
- UTF-8-aware cursor boundaries;
- Left / Right / Home / End;
- Delete and Backspace;
- Up / Down history with the default `history` feature;
- Tab completion with the default `completion` feature;
- Ctrl-A / Ctrl-E;
- Ctrl-U / Ctrl-K / Ctrl-W;
- Ctrl-C;
- Ctrl-L;
- bounded history using `heapless::Deque<heapless::String<LINE>, HISTORY>` when `history` is enabled.

Cursor keys are accepted in both CSI (`ESC [ A`) and SS3 (`ESC O A`) form, since terminals switch
to SS3 in application cursor-key mode.

The editor redraws using ordinary ANSI/VT100 sequences.

## Telnet layer

The runtime includes a byte-at-a-time Telnet codec rather than assuming a TCP stream contains only
terminal data.

Implemented protocol behavior includes:

- RFC 854 `IAC` command framing;
- escaped `IAC IAC` data bytes;
- WILL / WONT / DO / DONT negotiation with Q-method-style per-direction state tracking;
- BINARY negotiation and a framed `BinaryMode` transport for byte-exact protocols such as YMODEM;
- ECHO;
- SUPPRESS-GO-AHEAD;
- NAWS window-size negotiation;
- TERMINAL-TYPE negotiation and `SEND` request;
- subnegotiation framing;
- Interrupt Process, Break, Are You There, Erase Character, and Erase Line handling;
- Telnet-safe output (user `0xff` bytes are doubled automatically);
- NVT CR/LF input normalization at the editor boundary.

Echo is negotiated rather than assumed. The session offers `WILL ECHO` at startup and echoes input
while that offer is outstanding, so typing works against clients that never reply; a client that
answers `DONT ECHO` is echoing locally, and the session goes silent instead of doubling every
character. `Telnet::us_enabled`, `him_enabled`, and `us_pending` expose the negotiated state.

Replies that do not fit the caller's buffer are never treated as sent: option state rolls back so
the request is retried, and a deferred TERMINAL-TYPE `SEND` is re-emitted on the next byte.
`Telnet::MIN_REPLY` gives the largest reply a single `feed` can produce.

For protocols that need byte-exact transport, `BinaryMode` requests BINARY in both directions,
waits for explicit agreement, strips TELNET framing on reads, and doubles `IAC` in payload writes.
It intentionally has no timer dependency: wrap `BinaryMode::negotiate()` in the runtime's timeout
primitive. Because the adapter is created before negotiation, a timed-out caller can use
`BinaryMode::abort()` to request NVT mode before handing the connection back to the interactive
shell. `BinaryMode::finish()` performs the normal BINARY-to-NVT transition after a transfer.

RFC 2217 COM-PORT-CONTROL is deliberately not coupled to the CLI core. It can be added as a protocol
extension without contaminating command parsing or the terminal editor.

## `embassy-net`

The core depends on `embedded-io-async`, not Embassy itself. Current `embassy-net` TCP sockets
implement these traits, so no adapter is necessary.

An optional `embassy-net` feature exists only to compile the integration example:

```toml
microtun-cli = { version = "0.4", features = ["embassy-net"] }
```

See `examples/embassy_net.rs`.

## Fixed memory

Session capacities are explicit const generics:

```rust,ignore
Session::<_, 256, 8, 192, 16>::new(socket, config)
```

means:

- 256 bytes maximum editable command line;
- 8 history entries, each bounded by the line capacity;
- 192 bytes of internal session `core::fmt` scratch storage;
- 16 completion candidates offered per Tab press.

The last parameter defaults to 16. Raise it for a CLI with more options than that on one command,
since candidates past the limit are dropped.

Other bounded internals use `heapless` too: tokens, completion candidates, Telnet subnegotiation,
terminal type, parser bookkeeping, and negotiation output.

The only ordinary raw arrays in the session are short read/write byte buffers where an array is the
natural I/O representation rather than a collection abstraction.

## Renamed dependencies

Generated code names the runtime crate by path. If the dependency is renamed in `Cargo.toml`, tell
the derives where to find it:

```rust,ignore
#[derive(Parser)]
#[command(name = "device", crate = ::mt)]
struct Cli { /* ... */ }
```

## Schema stability

`ArgSpec`, `CommandSpec`, `RootSpec`, and `ValueSpec` are built by generated code living in *your*
crate, so adding a field to one of them would otherwise be a breaking change. Each carries a
`DEFAULT` associated constant and every generated literal ends in `..Spec::DEFAULT`, which keeps
field additions additive. Hand-written specs should follow the same pattern.

## Argument ordering

Within one struct, arguments are parsed in this order regardless of declaration order: named
options and flags, then `#[command(flatten)]` groups, then this struct's own positionals, then the
`#[command(subcommand)]` field. Options have to be claimed before any positional is taken,
otherwise a positional would swallow an option's value; flattened groups may contribute options,
so they are resolved first. The consequence is that a flattened group's positionals bind before
the outer struct's, which differs from `clap`. Generated help and completion follow the same
order, so what is displayed matches what is parsed.

Duplicate names declared directly within the same derived struct or enum are rejected at compile
time. Two direct fields that resolve to the same short or long flag, or two variants that answer to
the same command name or alias, are a build error rather than a silent first-match-wins. The macro
does not currently check collisions introduced across a `#[command(flatten)]` boundary, so flattened
groups should use option names that are distinct from their outer struct.

## Feature flags

Default:

```text
derive
help
completion
history
```

Optional:

```text
alloc
defmt
embassy-net
```

For the smallest runtime:

```toml
microtun-cli = { version = "0.4", default-features = false }
```

This leaves the transport, Telnet codec, lexer/parser traits, editor primitives, and schema types
available without the proc-macro dependency or optional interactive conveniences. If `help` is
disabled while using `Session`, consider `Config::help_hint(false)`: the parse-error help hint is a
separate configuration setting and defaults to `true`.
